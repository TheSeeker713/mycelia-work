# Devlog — Stopping to Take Stock

**2026-08-02, 12:59**
**Author: Jeremy Robards, CTO & CAIO, Mycelia Interactive LLC**

I want to be upfront about something before this devlog goes any further. This whole build, the app, the phases, the tests, all of it, is being built in collaboration with Claude Code, Anthropic's coding agent. I'm directing it, making the calls on architecture and scope and priorities, reviewing what it produces, but the actual typing and test writing and file structure is coming out of that collaboration. I don't see any reason to hide that. If anything I think it's more honest to say it plainly in the build log itself instead of pretending this is a solo effort.

So today I had to stop it mid phase. Three phases in, scaffold, data layer, task dashboard, all of it committed, tested, pushed, looking clean. But it kept going straight into phase three without pausing for me to actually look at anything or approve moving forward. That's not what I asked for. I want to see each phase before the next one starts, and if a phase touches the actual UI I want to click through it myself before anyone calls it done. Reading a green test suite is not the same thing as me looking at a window and deciding it feels right.

I also asked point blank whether there were any instructions or agent files wired into this project that would have enforced that process automatically. There weren't. No CLAUDE.md, nothing. That's on me for not setting it up before we started, and it's the first thing getting fixed once we resume, so this doesn't happen again on autopilot.

Rather than just take my word for where things stand, I asked for a real audit. Not a summary from memory, an actual check against the repo, the tests run again, the files read. That report is sitting in docs/audit_2026-08-02_1259.md now. Short version of what it says: phases zero through two are solid, tested, twenty four passing tests, clean commits, nothing to worry about there. Phase three has some draft logic sitting uncommitted on disk, and one of those files actually has a real bug in it right now, calling Date.now directly inside a React render function, which the linter caught. Good that it caught it. Everything past that point in the plan, the actual timer, the AI journal, the notifications, none of it exists yet.

So now I've got a clear picture instead of a vague sense that things were moving fast. I can decide from here whether to keep going from exactly where we stopped, revise some part of the design first, or scrap it and restart. I don't think scrapping it makes sense given how clean the first three phases are, but I wanted the option laid out honestly instead of assumed away.

Taking a beat here before deciding. That's the right call.

— Jeremy
