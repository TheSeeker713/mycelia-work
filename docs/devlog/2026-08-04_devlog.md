## 07:24 — Phase 11.1: a real watchdog and a real subprocess kill switch

Phase 11 - resource management. Added `sysinfo` for real CPU/memory
reads, kept as Tauri-managed state rather than recreated per call,
since a fresh `System` enumerates every process on the machine each
time and sysinfo's own docs say CPU-usage accuracy needs two readings
with real time between them anyway - a cold instance would report 0%
on every single check. Thresholds: 85% CPU or 90% memory counts as
under pressure, either one alone is enough to trip it.

The bigger find was in code that's been sitting there since Phase 6:
`call_agent`'s subprocess call used `Command::output()`, which blocks
completely until the child exits, with the *CLI's own* `--timeout`
flag as the only thing standing between a hung `openclaw` process and
a permanently frozen Rust call. If the CLI hangs before it even gets
around to honoring its own timeout, there was and is no way for this
app to get control back - `--timeout` is a request to the child, not
an enforcement mechanism this app actually holds. That's the literal
gap "subprocess timeout/cancellation" in the plan is naming. Rewrote
it to spawn the child directly, poll for exit against a real Rust-side
deadline, and kill it if that deadline passes - a genuine backstop,
not a second copy of the same hope. Had to drain stdout/stderr on
their own threads while polling instead of reading them after the
fact, since `output()` does exactly that internally for a reason: read
nothing while a chatty child fills its pipe buffer and it can't finish
writing, which means it never exits, which means the timeout never
even gets a chance to trigger. Applied the same real timeout to the
daemon status/start/
stop calls too, not just the model call.

contract as every other client in this app). Next: actually wire
