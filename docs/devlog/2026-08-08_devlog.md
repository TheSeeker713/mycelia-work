## 22:55 — Pocket/fullscreen state-loss bug, fixed structurally

This was the img2 bug from last night's report — start a new project in
pocket mode, expand to full screen, come back, the form's gone. Root
cause was structural, not Projects-specific: `Dashboard.tsx` had two
separate `return` statements for pocket vs. fullscreen, each rooted in
a different shell component (`PocketShell`, `FullscreenShell`) with a
different number of wrapper `div`s. React tears down and rebuilds an
entire subtree whenever the root element type changes between renders
— so `CompartmentContent` (and every compartment's own local state
underneath it) got fully unmounted on every pocket↔fullscreen toggle.
Todos' draft, Library's export state — same landmine, just not yet
reported.

Replaced both shells with one `Shell` component (`mode: "pocket" |
"fullscreen"`), same two-`div` wrapper shape either way, varying only
classes/style by mode. `Dashboard` now has one return path for pocket/
fullscreen — the chrome bar (`MenuBar`/`DeviceBar`), content padding,
and the overlay priority chain all branch on `controls.fullscreen` by
*value* inside one JSX tree, not by picking between two different
trees. Zen mode stays a separate branch on purpose — its draft already
lives in `useNotesStore`, not local state, so it was never actually at
risk — but now renders through the same `Shell` in fullscreen mode too,
one shell component total instead of two-going-on-three.

Two new tests prove the actual fix, not just "nothing broke": type a
project title, expand to full screen, come back, title's still there.
Same for an in-progress todo. Both would have failed before this
change and pass now.

Full suite 500/500, typecheck/lint clean. Rust untouched. Commit
`563255e`, pushed.

## 23:10 — Pocket height + app-wide scroll consistency

Grew the pocket card from 480 to 540px content height (680px window),
per Jeremy's "a little taller." The real work here was less the number
and more that it had been living as three independent hardcoded
copies (`Shell.tsx`, `useWindowControls.ts`, `useMultiCardWidth.ts`) —
found during Phase 15's own planning pass, and it's exactly the kind of
duplication that lets a window silently snap back to the wrong size

had zero scroll handling before this (the clearest gap from last
night's audit) — fixed alongside Projects, Todos, Notes, and Library,
whose per-section wrappers each clipped their own scroll independently,
meaning a long list plus an open form or section could push content
