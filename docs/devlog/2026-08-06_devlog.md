Bigger architecture change: every badge/sticker concept now maps to an
image POOL instead of one fixed file. The toast rolls a random pick
from the pool each time - that's the actual "reward moment" - while
the Progress tab's persistent grid shows a stable representative image
so the collection view doesn't shuffle under your cursor on every
re-render. Wrote a test that asserts all 98 curated image files are
referenced by exactly one pool, so nothing curated silently goes
unused - real value doing this as an assertion instead of a manual
count, since a typo in one of the ~40 hand-typed filename lists would
otherwise fail silently.

Also had to rebuild xp_events without its CHECK constraint - the fixed
enum for `source` couldn't keep pace with how many new XP sources this
added, and SQLite can't ALTER a CHECK constraint directly. Four new
single-statement migration entries (create-copy-drop-rename); the
TypeScript XpSource union is the real type safety now.

The new tests immediately caught a real bug before it shipped:
`unlockStickerOnce` was persisting the DB unlock but never updating
the in-memory `unlockedAchievements` state, so every first-time/
count-milestone achievement would've silently never appeared in the
UI until the next app restart. Exactly the kind of thing that "looks
right on paper" - glad it was caught by a failing test and not by
Jeremy wondering why his stickers weren't showing up.
